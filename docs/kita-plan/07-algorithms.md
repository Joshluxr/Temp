# G. Deterministic algorithms and state transitions

2026-11-09. This is normative proposed business behavior; provider/regulatory applicability remains unverified pending owner/counsel. Policy changes require versions and tests. No production fallback to a fixture.

## G1. Exact arithmetic and quote creation

Represent money `M=(currency,minor:bigint)`. Represent rate PHP-per-USD as positive rational `(n,d)` derived losslessly from provider decimal text. Bound amount≤9,000,000,000,000,000 minor units (stricter capability limits normally apply); bound rational numerator/denominator≤10^24 and all intermediate products in arbitrary precision. Parse decimal with a strict regex, scale by the configured exponent, reject fractional minor units, then enforce corridor/customer/rail limits. Never pass a monetary value through JavaScript Number, including formatting above 2^53.

For principal P source-minor, source exponent es, destination exponent ed:

`receive = floor(P*n*10^ed / (d*10^es))`.

Customer rate with markup b basis points: `nCustomer=nWholesale*(10000-b)` and `dCustomer=dWholesale*10000`, reduce by GCD. Rate display is rounded to6 decimal places but execution uses the original rational. Rate improvement promotion affects only its bounded principal tranche; compute tranche receives independently, sum exact rationals, then round once. Persist tranche amounts, rates, and remainder. No transfer splitting to evade rail limits.

Exact-recipient mode R: `P=ceil(R*d*10^es/(n*10^ed))`. Set promised payout **exactly R**, not recomputed floor(P*rate), because the latter can exceed R by multiple centavos for a single source cent. Disclose effective rate `R*10^es/(P*10^ed)` and rounding adjustment. The difference from the quoted formula is bounded by one source minor unit's converted value and belongs in realized spread, not an unreported recipient reduction. Reject if provider cannot deliver exact R. At57.42 and targetPHP1,000.00, P=USD17.42 (1742 cents); formula valuePHP1,000.2564, but payout exactlyPHP1,000.00 with explicit rounding remainder. For JPY source, the same rule uses es=0.

Fee policy F1: select exactly one nonoverlapping principal tier `[min,max)`; base fee=`fixed+ceil(P*percentBps/10000)`; clamp to tier min/max; add separately disclosed funding/payout surcharges; round each tax component only under its jurisdiction-approved rule. Positive-rate US example fee399 cents, b=100, P50000, source58 → receive2871000, total50399. Unsupported tax rule is `POLICY_UNAVAILABLE`, never silently zero. Promotion precedence: one code OR points, then mutually exclusive referral qualification benefit; no stacking at launch. Discount≤eligible fee, never principal; total=P+grossFee-discount+tax. Rate boost cost must fit campaign budget and margin floor including expected provider costs.

`buildQuote`: authorize → capabilities/recipient-version/instrument/risk checks → obtain executable vendor quote outside DB transaction → enforce timestamp/max age10s and vendor expiry → exact computation → evaluate delivery calendar and risk exposure → transaction recheck policy versions and persist immutable quote/terms. Acceptance expiry=`min(now+60s,providerExpiry-5s)`; if less than10s remains, reject/requote. Public indicative calculator returns no executable quote ID, and clearly labels estimate/time. Missing liquidity, stale rates, impossible delivery promise, or pricing policy disables executable quoting.

## G2. Quote acceptance and reservations

1. Authenticate/step-up as policy requires; validate request and canonical hash; take durable command-key lock. If existing key and matching hash return operation/result; mismatch409.
2. SERIALIZABLE transaction locks customer, draft/quote, current recipient version, limit buckets, campaign, and relevant balance/liquidity rows in globally specified order. Use database time; expiry boundary is `now >= expiresAt`.
3. Verify quote ownership, one-use uniqueness, recipient version, funding mandate, disclosed terms hash and locale consent, entity/residency permissions, screening/identity freshness, no blocking holds, and current exposure/limits. A changed destination requires a new quote and consent.
4. Reserve daily/monthly velocity, promo/points budget, FX risk capital, and payout principal plus fees in the appropriate pool. Available liquidity=`confirmed eligible asset balance - active reservations - operational buffer`; pending inbound deposits count zero. Wallet reservations post in this same transaction.
5. Create transfer, consent, event, outbox, timer and command result atomically. HTTP201 means durable acceptance, never payout. Funding initiation deadline default15 minutes after acceptance for card; ACH mandate initiation15 minutes, settlement promise based on contracted calendar. Treasury must accept the full disclosed settlement-window exposure before a binding offer.
6. On network loss retrieve command result by operation/key; never mint another transfer key. A quote can be accepted only once even with two different keys.

Approved policy changes that make an unaccepted quote unsafe may reject acceptance. Already accepted commercial terms persist; legal restrictions create holds, not retrospective customer repricing.

## G3. Funding and eligibility

Instrument creation uses hosted provider tokenization. Bind token to customer, entity, mandate, permitted currency/method, and verified ownership. ACH submit creates an attempt and no money. Card authorize creates no money; authenticated capture posts receivable/pending/deferred fee; actual settlement posts net cash/cost/reserve. Availability decision records policy, signals, amount, expiry, and approved capital exposure. Initial ACH rule requires settlement; post-settlement return handling remains mandatory. Debit Express additionally requires approved advance limit and corporate prefund. Credit-card funding is disabled until remittance/MCC and issuer disclosures are approved.

Never automatically re-debit a returned ACH from a generic error class. Adapter supplies return code; current scheme/mandate-specific reinitiation policy determines whether a new instruction is legal. Unknown funding status is queried under the original identity. Late funding for a cancelled/expired transfer becomes pending/suspense and a refund case; it never resurrects a payout silently.

## G4. Independent attempt state machines

| Leg | Legal progression | Exception transitions / accounting |
|---|---|---|
| Funding | queued→submitting→pending→authorized→captured→settled | ACH pending→settled; unknown→verified current state; rejected/cancelled only with definitive evidence; settled/captured→returned records separate return |
| FX | queued→submitting→accepted→settled | timeout→unknown; definitive no-trade→rejected; never retry with a fresh key while unknown |
| Payout | queued→submitting→accepted→pending→paid | accepted→paid allowed; unknown→paid after evidence; rejected/cancelled permits new authority; paid→partially_returned→returned preserves payment history |
| Refund | queued→submitting→pending→paid | unknown requires inquiry; rejected/cancelled releases attempt reservation only; paid→returned restores refund obligation if still owed |

`attempt_edges` in DDL encodes allowed transitions; service enforces leg-specific capabilities and business gates more narrowly. Missing intermediate events are reconstructed only from authenticated inquiry or attested terminal evidence, in order in one transaction. Do not manufacture intermediate provider events. The event mapper records implied facts and mapping version. A late pending event after paid is retained as evidence but does not regress state. A return is a distinct economic event, never a stale status to ignore.

## G5. Payout submission authority and hold race

Authorize in one transaction: lock transfer and payout attempt, verify current customer/compliance/quote/recipient/permissions; lock liquidity; reserve amount+cost; create stable attempt reference; emit task. At dispatch lock the same transfer first, then attempt and current holds. Recheck global/route switches, screening list version, exposure, approval validity, recipient, and liquidity. Atomically change queued→submitting and increment fencing generation. Commit; only then call provider. Never hold DB locks across network.

The dispatch commit is the linearization point. A hold committed before it prevents submission; a hold arriving after it records `submission_in_flight` and starts provider cancellation/inquiry where supported. UI cannot promise it stopped an already in-flight payment. A lease expiry alone never authorizes another submit for an unknown operation. Provider idempotency plus stable external reference is required; generation fences DB effects, not a remote provider. If the provider lacks safe dedup and authoritative inquiry, unattended payout on that route is disabled.

Worker result is applied under expected version and generation; a stale worker may append its verified evidence but cannot overwrite a newer reducer decision. Crash after provider acceptance but before local write leads to inquiry under the original external reference. Retry may reuse the identical key within the provider's documented window only when its contract guarantees duplicate suppression; after the window, query/reconcile first.

## G6. Routing, FX, and liquidity

Filter routes by entity authority, corridor, beneficiary institution/method, currency, amount, funding compatibility, capability freshness, compliance, hard health status, liquidity, and delivery promise. Among eligible routes sort by all-in cost in source currency; tie-break lower measured p95 delay, then provider ID for determinism. Cost uses executable FX, processor cost, payout fee, expected loss and working-capital cost; no undocumented weight blending. Record candidates, exclusion reasons, chosen route and policy versions. Circuit open excludes new work but preserves inquiries/returns.

Accepted transfers keep promised amount/cost. Reroute requires independent approval and proof previous attempt is nonpaying or cancelled with contractually final confirmation; temporary not-found is insufficient. Release old liquidity only upon proven no debit or actual returned cash. Reserve new route before dispatch. If a route requires new recipient details or materially changes terms, obtain a new recipient version/disclosure and consent; never redirect in-flight payment. If no safe route exists, hold and meet remedy deadline from corporate funds when required.

FX `executeConversion` buys exact payout currency amount at actual source cost C. Record quote/ref, trade ID, value date, fees, and both currency postings E4/E6. Reject amount deviation before execution; after an unknown outcome query trade ID. Prefund movements require bank/provider settlement evidence. Available external balance is conservative minimum of ledger-derived eligible cash and latest reconciled provider available balance, less reservations/buffer; stale/contradictory evidence pauses new exposure.

## G7. Webhooks, outbox, timers, and retry

Ingress: enforce size256KiB by default (provider-specific approved override), exact raw bytes, authentication/signature scheme and timestamp tolerance per provider, allowlisted account/environment, constant-time MAC comparison where applicable, replay checks, schema validation. Store inbox and encrypted raw evidence object hash before2xx; if DB unavailable return5xx to request retry. Same delivery ID/same hash→ack existing; same ID/different hash→quarantine/security case. If callbacks are not cryptographically authenticated, treat them only as inquiry hints; no monetary posting until authenticated API/report confirmation.

Reducer transaction locks attempt/transfer, deduplicates business event as well as delivery ID, verifies amount/currency/beneficiary/provider account, applies legal transitions, posts typed journals, adds events/notifications/outbox, marks inbox applied. Unknown codes quarantine; preserve raw code. Return/partial return requires unique movement identity and cumulative amount checks.

Outbox publisher claims with `FOR UPDATE SKIP LOCKED`, 30s lease, publishes stable event ID to SQS, marks published only after send acknowledgment. Crash after send re-publishes same ID; consumer-inbox insert and domain changes commit together before queue ack. Retry transient transport/5xx/429 with full jitter up to60s, maximum8 immediate attempts, honoring Retry-After. Financial ambiguity bypasses blind retries and schedules inquiries at15s,60s,5m,15m,60m then hourly, adjusted to contractual SLA. Escalate unknown payout after5m; never declare failed solely by age. DLQ replay preserves IDs, requires authorization and reason, and cannot change an attempt payload.

Timers store generation and due time; claim with lease; recheck current state/generation before firing. Deploy/restart never discards deadlines. Use DB UTC for ordering; occurrence time from signed provider is separately retained; alert on clock skew>1s. Business deadlines derive from named legal calendars and versioned cutoffs.

## G8. Cancellation, refunds, disputes

Timestamp any customer or support cancellation at ingress before investigation, store original channel/agent receipt time, case and deadline. Serialize against dispatch. Before dispatch cancel safely and reverse only actual obligations; after submission inquire/cancel; proof of recipient credit at request time determines policy. An eligible refund is recognized when owed, not when an operator clicks approve. Deadline scheduler escalates to staffed Finance, funded exceptional remedy, and Compliance; uncertain provider status is not an indefinite excuse to miss customer rights. See I for the proposed US rule inputs and E for every journal.

Refund cap transaction locks transfer, all obligations, successful/pending/unknown refund allocations, provider returns and dispute credits. Normal cumulative principal≤collected principal not already restored; fees/taxes per remedy policy; goodwill requires separately funded authorization. Reserve refund amount before dispatch; unknown refunds retain reservation. Any overlap unresolved by evidence goes to case resolution; automatic duplicates are prohibited. Partial allocation uses cumulative rounding from E9. Original instrument is default destination; alternate payment requires lawful policy, identity verification, independent approval, and immutable destination evidence. Never refund sanctions-blocked property without the applicable legal release.

Post-payout ACH return/chargeback never changes paid to failed. Open recovery case, post evidence-based loss/receivable, restrict new exposure, submit contest evidence by due date, and reconcile final credit/loss. Payout returns create new obligations; no automatic resend without current destination validation, eligibility, a safe authority, and consent if changed.

## G9. Wallet, rewards, promotions, referrals

Wallet balance query shows available/pending/reserved separately. Concurrent spend uses one SERIALIZABLE transaction and ordered account locks. Reserve by moving liability available→reserved, then consume/release through typed events. No negative availability; debt/return recovery is separate. Withdrawal, conversion, closure and deceased-customer handling use the same entitlement and evidence controls. Customer-to-customer wallet transfer, if enabled, Dr sender available / Cr recipient pending in same currency/book; screen both, apply limits, then release under policy. Cross-book P2P needs intercompany settlement and remains disabled without it.

Points `reservePoints` locks customer and unexpired vested lots ordered expiry/ID; sum available units after prior reservations; consume enough lots, atomically reserve campaign cost; commit at successful qualified fee use, release on safe failure. Expiry only unreserved units; reserved quote points follow acceptance expiry then release/expire. Reversal records original lot/source, never deletes. Vest/expiry scheduler uses unique source+rule+event keys; chargeback before vest cancels earn; after redemption records noncash reward debt and review.

Campaign locks enforce total budget and customer/device/instrument/recipient caps atomically. Quote display is conditional until acceptance reserves entitlement. Failed/expired transfers release reservations; delivery consumes once. Referee has at most one referrer; never self-referral, first qualifying transfer only, same household/device signals cause review rather than automatic accusation. P1 proposed referral benefit500 points each after USD100 qualifying principal, KYC and30-day vest, monthly10 referrals/referrer; gate economics and lawful terms before activation.

## G10. Alerts, auto-conversion, schedules, bills, batches, stablecoins

Alerts compare requested basis only on fresh snapshots, dedup alert+snapshot; trigger threshold crossing, cooldown24h, rearm after moving0.1% back across threshold, expiry90d, max20 active/customer. Informational alert never spends. Open fetches a new quote. Notifications dedup event/customer/template/channel; unknown vendor delivery does not create another success message without provider inquiry or documented at-most-once preference.

Auto-conversion is a separate explicit wallet mandate: currency pair, target net rate, maximum source amount, maximum daily/total amount, minimum receive, fee ceiling, expiry≤30d, execution-count cap, and revocation version. Initial enabled policy is one-shot funded-wallet only. On crossing, lock mandate, verify unrevoked and limits, obtain fresh executable quote, require net rate≥target and all bounds, reserve funds and mark mandate executing atomically. Each occurrence has one operation ID. If quote cannot meet bounds, remain armed; if balance/compliance fails, pause and notify. No bank debit from an alert. Completion consumes mandate; unknown retains it and inquires. Add server consent and receipts as for transfers.

Scheduled transfers: initial implementation sends reminders/new consent; automated mode only under separately approved recurring mandate with per-occurrence amount/rate/fee limits and advance notices. Unique(schedule,occurrenceUTC) prevents DST duplicates; store intended local wall time and calendar. Missing consent/funding→skip with notice, never catch-up debit without authorization. Cancellation of future occurrences does not silently cancel submitted ones.

Bills use immutable biller schema/version, normalized account token, due period and validated amount. Acceptance is not posted; final biller posting evidence completes obligation and proof. Duplicate biller-account-period submissions are flagged; actual partial/reversed postings create cases and explicit refund journals. No claim that remittance rail acceptance proves bill settlement.

Batch payouts are a KYB product. Validate encrypted CSV with formula protection; create one item draft/quote/approval allocation per row. Batch approval binds ordered item hashes and total/currencies; changes invalidate it. Dispatch each item through normal gates. Partial batch success never rolls back paid items; rerun only definitively unsubmitted items with their original identities.

Stablecoin treasury is disabled at launch. If approved, use institutional custody; asset=(issuer,contract,network,decimals) atomic units, no fiat exponent reuse. Approve allowlisted destination/network and capped amount; ledger tracks fiat on-ramp, custody asset, network fee, confirmed transfer, off-ramp receivable, PHP settlement separately. Pending chain receipt is not fiat payout. Reorg reverses provisional confirmations via events, freezes related available liquidity; depeg threshold0.5% stops new trades and triggers treasury review. No automatic alternate-chain retry; reconcile nonce/hash and custodian ID. Fiat refunds remain funded in source currency. Exact chain/finality/custodian policies must be signed before activation, not guessed in application code.

## G11. Short, excess, duplicate and late funding

The expected collection is the accepted quote's **total**, not principal alone. Match verified movement currency, gross amount, owning customer, provider account, instruction reference and event identity. A net settlement after explicitly itemized fees/reserves is not short customer funding: E5 separates the receivable, cash, expense and reserve. An unexplained gross mismatch cannot be made good by reducing the recipient amount or treating missing cash as received.

Initial short-funding policy: for expectedUSD503.99 but independently proven gross collectionUSD499.99, post Dr actual bank499.99 / Cr identified-unallocated-customer liability499.99; mark collection amount exception, keep payout authority blocked, and create the customer remedy case. Do not allocate the full500 principal or3.99 fee, and do not automatically debit the missing4.00. Initial product does not support assembling partial collections: on definitive short receipt, recognize refund499.99 from the unallocated liability, charge no transfer fee, and execute E7. Customer may create a new transfer using a fresh quote/consent after recovery; no silent resurrection or use of unrelated wallet money. If evidence proves an in-flight balance of the original instruction, keep the instruction unknown/pending and inquire until its final gross outcome is established, while remedy deadlines continue.

Excess-funding policy: for a verified intended collectionUSD510.00 against503.99, allocate the accepted503.99 once (principal500 and deferred fee3.99); credit excess liability6.01, then refund that excess through a separate obligation tied to the exact incoming movement. Dr bank510 / Cr pending principal500 / Cr deferred fee3.99 / Cr excess liability6.01. Dr excess liability6.01 / Cr refund payable6.01. Proceed with the original transfer only when eligibility and the expected portion's availability are proven; excess is never revenue, a larger payout, or implicit wallet top-up. Unknown ownership goes entirely to unidentified suspense until attributed. Sender refund caps include both original entitlement and separately evidenced excess; allocation cannot reuse the same incoming units.

Duplicate callback for one movement is deduplicated and posts nothing new. Two distinct actual collections are two real receipts: first funds the one accepted transfer, second remains customer/unidentified liability and triggers recovery/refund; never discard real second cash as a mere webhook duplicate. A late receipt after cancellation or an expired **unaccepted** offer goes to suspense/unallocated liability and refund, with no payout. A valid accepted quote waiting on its already-authorized funding remains binding under G2/E6; do not misclassify normal settlement delay as offer expiry. Use `received_at`, actual economic time and the original accepted instruction to distinguish these cases.

T-FUND-07/T-FIN-04 implement these branches under T-LEDGER-02's typed templates and allocation locks. Tests compare gross statement records, exact bank/liability journals, zero extra collection instructions, UI amount-exception/refund messaging, and source-event/case/consent audit links.
