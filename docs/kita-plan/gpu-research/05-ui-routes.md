- **Routes unreachable from nav**: none of the 12 routes is orphaned; customer nav (`AppShell.tsx:73-78`) covers `/app,/send,/recipients,/wallet`; admin nav (`AppShell.tsx:80-86`) covers all five `/admin*`; `/transfers/:id` reachable from Dashboard rows (Dashboard.tsx:192) and Wallet (Wallet.tsx:261).

## State and data plumbing

- Providers: `main.tsx:9-17` → `StrictMode > BrowserRouter > TRPCProvider > App`. `TRPCProvider` (src/providers/trpc.tsx) mounts `trpc.Provider` + `QueryClientProvider` with a module-level singleton `new QueryClient()` — **no defaultOptions**, so React Query defaults apply (3 retries, staleTime 0) except where individual calls override.
- tRPC client: `httpBatchLink` to `/api/trpc`, `superjson` transformer, custom `fetch` adding `credentials:"include"` (cookie session). Typed against `AppRouter` imported from `../../api/router` — the SPA shares source with the server folder (also aliased in vite.config.ts: `@contracts`, `@db`, `db`).
- Server surface (api/router.ts): `ping`, `auth` (`me`, `logout` — api/auth-router.ts:7-8), `remittance` (16 procedures, api/remittance-router.ts:49-281), `admin` (10 procedures, api/admin-router.ts:130-313). Session cookie verified in `api/context.ts:16` (`authenticateRequest(headers)`), i.e. auth originates server-side; the client never stores a token.
- Auth state: single hook `src/hooks/useAuth.ts` — `auth.me.useQuery({staleTime:5min, retry:false})` (:24-27), `auth.logout.useMutation` that `await utils.invalidate()` then `navigate(LOGIN_PATH)` (:29-35), optional redirect effect (:37-42). `LOGIN_PATH="/login"` from `src/const.ts` (the entire file). Guard placement is per-page via `AppShell`, not router-level.
- Invalidation discipline: consistently targeted, mutation-scoped invalidation — e.g. `utils.remittance.workspace.invalidate()` after every wallet/send mutation (Wallet.tsx:16-19; SendMoney.tsx:34,39,44), multi-route fan-out on admin actions (`Promise.all([...listTransfers, transferDetails, overview, reconciliation].invalidate())`, AdminTransactions.tsx:45; AdminConfiguration.tsx:30). Only two queries poll: `admin.listTransfers` 10 s (:38) and `admin.overview` 15 s (:9). Customer transfer status does **not** poll (no `refetchInterval` on `remittance.transferDetails`, SendMoney.tsx:63 / TransferDetails.tsx:15).
- Form state: plain `useState` objects per page (SendMoney.tsx:19-28, Recipients.tsx:287-290, Wallet.tsx:228-231); `react-hook-form` and `zod` are dependencies but Zod is used client-side nowhere in `src/` (grep: no `zodResolver`; zod appears only in `api/*-router.ts` inputs).
- Toasts: `sonner` ^2.0.7 is installed and `components/ui/sonner.tsx` exists, but **no `<Toaster>` is mounted and no `toast()` call exists in `src/`** (grep). Feedback is instead per-page `notice` state banners (Wallet.tsx:231,241; AdminTransactions.tsx:36,64; AdminCompliance.tsx:18,30) plus inline `role="alert"` error paragraphs.
- Hooks: `useAuth.ts` (callers: AppShell.tsx:89, AdminConfiguration.tsx:20 & :64, AuthLayout.tsx:49 & :110 [dead]); `use-mobile.ts` (caller: AuthLayout.tsx only → dead). Client logging: `src/lib/logger.ts` posts to `/api/log` via raw `fetch` (:127), imported for side effects at `main.tsx:1`. Number/currency/date formatting centralized in `src/lib/format.ts` (`usd` en-US, `php` en-PH, `shortDate`, `dateTime`, status/payout/payment label maps).

## UX gaps that matter for a financial product

- **UX-01 Money-action confirmation**: `createTransfer` is one click from the review step with only a disclosure checkbox gate (SendMoney.tsx:153,156); no AlertDialog re-stating amount/rate/recipient before commit. By contrast destructive admin actions and recipient deletion do have confirm sheets (AdminTransactions.tsx:119; Recipients.tsx:335) — inconsistent pattern.
- **UX-02 Idempotency visible to user**: no idempotency key is generated client-side for any mutation (none in SendMoney/Wallet mutate calls); protection relies entirely on `disabled={…isPending}` (SendMoney.tsx:156) and server-side keys mentioned only in copy (TransferDetails.tsx:443 "idempotency keys"). Double-submit after a slow response or a lost-success race is unmitigated in the UI (inferred).
- **UX-03 Status polling / webhook surfacing**: customer-side `transferDetails` has no `refetchInterval` and no websocket; after creation the result query fires once (SendMoney.tsx:63) and the tracking page stays static until manual reload (TransferDetails.tsx:15). Copy explicitly promises partner webhooks exist only in production ("Production partners would send signed webhooks", TransferDetails.tsx:421). Admin side polls 10/15 s (AdminTransactions.tsx:38, AdminOverview.tsx:9).
- **UX-04 Missing error surfaces on mutations/queries**: `mutation.error` is never rendered in AdminTransactions (file contains no `.error` JSX for `mutation`/`list`/`detail`), nor `workspace.error`/`rate.error` in Dashboard, nor `list.error` in AdminCompliance, nor `toggle`/`createAlert` errors in Wallet. A failed money-adjacent admin action can silently revert on next invalidation (inferred).
- **UX-05 Unvalidated numeric amounts**: amount fields are free text coerced with `Number()` and regex-sanitized character sets only (`replace(/[^0-9.]/g,"")`, QuoteCalculator.tsx:80; Wallet.tsx:247; Dashboard.tsx:206). Range rules live in `disabled` predicates (QuoteCalculator.tsx:58, Wallet.tsx:247 `$10–$5,000`) and server Zod (api/remittance-router.ts:34,242). Locale decimal separators, multiple dots (`"1.2.3"` → NaN), leading-zero and cent-precision behavior are unhandled client-side (inferred from code). Direction toggle labels the field "Amount in PHP" while the same `[0-9.]` filter and the help text still say "$10 to $10,000" (QuoteCalculator.tsx:77-83) — currency-boundary confusion.
- **UX-06 Accessibility**: good baseline — focus-visible ring on all interactive elements (index.css body rule), `aria-label`s on icon buttons, `role="dialog"/"alertdialog" aria-modal` on custom modals, `role="switch" aria-checked` (Wallet.tsx:267), `prefers-reduced-motion` reset. Gaps: custom overlays are hand-rolled divs, not Radix Dialog — no focus trap, no focus restore, no Escape handling found in AppShell drawer (AppShell.tsx:150-158), Recipients/SendMoney/AdminTransactions modals (e.g. Recipients.tsx:316, AdminTransactions.tsx:83); page `<h1>` hierarchy duplicated by `PageHeading`; SendMoney wizard progress `<ol>` conveys step state visually only (no `aria-current`, SendMoney.tsx:91-96); several hardcoded low-contrast combos (`text-[#f5f5f0]/45-.65` on ink panels, Wallet.tsx:247, Dashboard.tsx:172-176) cannot be verified statically beyond noting opacity-based text.
- **UX-07 Responsive/mobile**: deliberate breakpoints throughout (`lg:ml-64` sidebar offset, mobile drawer, `grid-cols-[1fr_auto]` → wide grids at `lg`, hidden columns on small screens in admin tables AdminTransactions.tsx:71-79 — meaning sender/amount/route/status are simply invisible below `lg`, leaving reference + risk only). Step labels collapse to numbers under `sm` (SendMoney.tsx:94).
- **UX-08 i18n/l10n for PH corridor**: `Intl` is hardcoded `en-US` for USD/dates and `en-PH` for PHP (lib/format.ts); dates always US-region format; PHP sometimes via `php()` and sometimes via raw `₱${toLocaleString()}` (AdminAudit.tsx:72,78) — inconsistent. No Filipino/Tagalog strings anywhere; no locale switch; `index.html lang="en"`.
- **UX-09 SEO/SSR**: pure client SPA — a single `index.html` shell with `<div id="root">` and module script; content (including marketing Home with anchor sections `#how/#coverage/#operations/#security`, Home.tsx:80-158) renders only after JS; PWA `navigateFallback: undefined` means server must rewrite unknown paths (vite.config.ts workbox block). No `<title>`/meta per route (only the static site title/description in index.html).
- **UX-10 Admin-area exposure**: admin routes are lazily importable by URL and their page components are bundled regardless of role; enforcement is (a) client render-block (AppShell.tsx:95-96) and (b) server `requireRole("admin")` (api/middleware.ts:46-56) — the server gate is the real control. Second-person approval is enforced server-side for config changes (api/admin-router.ts:272 self-review FORBIDDEN) and surfaced as `pendingApproval` results (AdminTransactions.tsx:44), but there is no dedicated approvals route; approvals live inside `/admin/configuration` (AdminConfiguration.tsx:30). Public Home links straight to `/admin` "Explore control room" (Home.tsx:140), advertising the ops surface.
- **UX-11 Sandbox honesty vs product readiness**: persistent "SANDBOX" badge (AppShell.tsx:145), sidebar notice "No real funds move" (AppShell.tsx:121-123), receipts watermarked "No real money was moved" (TransferDetails.tsx:365). KYC is simulated document-type selection with no upload (SendMoney.tsx:143-147).
- **UX-12 Login flow fragility**: `/login` depends on `import.meta.env.VITE_KIMI_AUTH_URL`/`VITE_APP_ID` with no presence check (Login.tsx:5-6); failure mode is an uncaught exception during render (inferred). No "already authenticated, skip login" logic anywhere.

## Migration sensitivity

Cheap to port (framework-agnostic or already idiomatic):
- All 45 `components/ui/*` shadcn/Radix primitives — stock output of `components.json` (`rsc:false`); they depend on `@/lib/utils` (6-line `cn`) and Tailwind tokens only.
- `src/lib/format.ts`, `src/const.ts` (one export), `src/lib/logger.ts` (plain fetch beacon to `/api/log`).
- tRPC wiring (`providers/trpc.tsx`) — `@trpc/react-query` + superjson + relative `/api/trpc` URL ports to any React framework; type import of `AppRouter` from `../../api/router` presumes co-located server code (vite aliases `@contracts`, `@db` also cross the src/api boundary — bundler-config coupling, not router coupling).
- Presentational page bodies: heavy Tailwind JSX moves nearly verbatim.

Deeply coupled to current routing/data-fetching:
- **Guard architecture**: auth + role checks are embedded in `AppShell`'s render path (`useAuth({redirectOnUnauthenticated:true})` AppShell.tsx:89; role branch :95-96), so every page inherits its guard implicitly via composition rather than via router configuration. Any router-object/layout-route refactor must relocate exactly this behavior for 12 routes.
- **URL-state contracts**: `/send?quote=<id>` (SendMoney.tsx:17-18 + effect :48-53) and `/admin/transactions?status=&transfer=` (AdminTransactions.tsx:28-31, `setParams` at :49-50) are load-bearing round-trips between pages; `QuoteCalculator` navigates to them by string (QuoteCalculator.tsx:129).
- **Imperative auth flows**: `useAuth` returns `navigate`-based redirect + `logout` that calls `utils.invalidate()` (useAuth.ts:29-35); Login performs a full-document `window.location.href` OAuth hop (Login.tsx:31-33) whose callback is a server route (`/api/oauth/callback`), i.e. session bootstrapping straddles SPA and Hono handler.
- **Cross-cutting cache graph**: pages assume specific query keys exist for invalidation (`remittance.workspace` is invalidated from SendMoney, Wallet, Recipients, TransferDetails; `admin.overview/listTransfers/reconciliation/transferDetails` from AdminTransactions.tsx:45). A server-component/RSC data model would need equivalents for this whole fan-out, including the two admin `refetchInterval` polls.
- **Server-shared types**: `AppRouter` type import and `@contracts`/`db` aliases mean front-end and back-end compile together today (vite.config.ts resolve.alias block).
- Dead-but-shipped weight: `AuthLayout.tsx` (266 ln) + `AuthLayoutSkeleton.tsx` + `use-mobile.ts` + most `ui/*` primitives are unreferenced by routes; they affect bundle analysis but not behavior.
